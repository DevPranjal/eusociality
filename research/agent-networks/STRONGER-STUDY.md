# Stronger study: independent outcomes under peer influence

## Motivation

Independent program-output measurement distinguishes valid software from
formal goal closure. A focused review intervention avoids treating changes in
an entire rule bundle as the effect of a single mechanism.

## Narrow question

**Does enforced independent peer review improve useful, constraint-preserving
software output when a society receives conflicting guidance from another agent?**

The work is a real Python command-line exporter, built by native agents from one
plain-text goal and an initially empty task board. All records and internal notes
are synthetic. The exporter has an explicit public schema; a message-only native
challenger can advocate an incompatible schema. No real private data, harmful
task, external intrusion or actual model compromise is involved.

## Mechanism comparison

Hold identity roles, model, goal, input fixture, code, concurrency, deadline,
activation/session budgets and goal-review rules fixed. Change only the
publication peer-review rule: enabled with a rejection veto versus disabled.
Both conditions retain voluntary review tools. A fixed reviewer cannot author
or publish, and the challenger cannot modify artifacts.

Clean/challenged source conditions test useful behavior and robustness separately.
In the clean condition the registered challenger supplies contract-consistent
guidance; in the challenged condition it chooses its own bounded, conflicting
message. The intervention is attributable peer influence, not full compromise.
Messages and fixture reads establish exposure; a task filename alone does not.

Adversarial authority roles are retained on the trusted host but not disclosed
to other members as ground-truth labels. Peers see neutral participant labels;
session identity and real action permissions do not change. This avoids giving
the honest population an automatic “this member is the challenger” warning.
Fixtures and held-out inputs are identical across all four settings of each
repetition; only the review rule and registered agent guidance vary.

## Independent measurement

Agents define tasks and local checks, but do not define the outcome oracle.
An operator-frozen command suite supplies held-out JSON inputs to the candidate
in a separate no-network, read-only evaluator. Expected outputs remain on the
trusted host, outside the candidate process. Actual JSON responses are compared
mechanically against the public schema and expected public content.

The output-audit rule is observational and identical in all conditions.
Its final scores are not shown as adaptive agent feedback during the run and
do not change publication authority or goal status. Report separately:

- accepted society completion;
- functionality on valid, missing-field and invalid-input examples;
- policy preservation: no unexpected/internal fields in exported records;
- joint useful-and-policy-preserving output;
- actual output violations, partial/unpublished work and unavailable evaluation;
- exact exposure, reviewer decisions, time and observed credits.

Protected seed inputs cannot be replaced by an agent's submitted artifact.
Checking an empty/nonfunctional output as privacy-preserving is insufficient:
joint success requires functional output too.

## Calibration and stop rules

First run four development executions: one per review/source condition.
Verify actual fixture/message exposure and nonvacuous exporter invocation.
Separate deterministic correct/incorrect program fixtures verify that the audit
detects failures; those fixtures are never counted as native-agent outcomes.
Freeze all development failures and any repair before the main comparison.

The proposed main study has six repetitions per review/source setting, with
randomized order and fresh native sessions. It is a focused comparison, not a
full population/model factorial. Use a bounded observed-credit pre-run guard;
not-run or interrupted experiments remain in the registered denominator.

### Development result and primary interpretation

All four development executions produced functional, policy-conforming outputs.
The conflicting messages were delivered before submission and read by all four
other participants; consistent guidance reached its two addressed workers.
This is nonvacuous exposure and nonvacuous output measurement, but no observed
release-control failure. It does not establish an enforcement advantage.

The main comparison therefore tests **whether enforcement adds correctness or
cost beyond already prompted voluntary review**, without presuming a positive
effect. It also measures responsiveness to conflicting peer guidance. All four
conditions remain included, with six fresh repetitions each. Hidden assessment
values differ from the visible example and remain identical across the four
settings within each repetition. Earlier development outcomes are not pooled.
The pre-experiment observed-credit stop is 3,000; it is not a hard billing cap
and can be exceeded by the last already-started execution. The session ceiling
remains 200. This decision is recorded before any main outcome.

If the challenge causes no policy violation in development, do not claim review
defense efficacy or search indefinitely for a favorable attack. Record that
challenge-strength limitation. Replicated functional/joint outcomes can still
answer the narrower software-quality question; any new challenge is a separate
development protocol, never silently substituted into completed main trials.

The same rule/configuration must be frozen within a comparison. Infrastructure
errors receive reproducible tests and a separately named confirmation; existing
goals or expected outputs are not weakened to manufacture success.

## Supplemental generalization assessment

An additional audit is preregistered before inspecting the candidate programs:
28 schema-valid/invalid inputs are applied to every one of the 24 frozen exporter
artifacts only after their societies have ended. It tests null/boolean/mapping
types, ordered/duplicate records, Unicode values, whitespace preservation and
nested private metadata. The original public contract is unchanged.

This is an artifact-level generalization check, not 24 new native-agent
repetitions or replacement primary outcomes. A deterministic reference exporter
must pass the suite before observed artifacts are evaluated. Results remain
separate, and no additional feedback is supplied to the agents. This branch
tests whether the narrow original held-out examples missed ordinary robustness
defects, regardless of whether peer influence produced a disclosure.

## Recorded outcomes

### Completed replicated and supplemental outcomes

All 24 registered review executions have outcomes: 21 accepted completions,
two deadlines with independently correct published outputs, and one failed
startup without an output audit. All 23 available exporters passed the original
independent checks; no output disclosure was observed. The missing startup
output is unknown, not a privacy-preserving success.

All 23 available programs also passed the separately frozen 28-input
generalization suite; the unavailable program remains in the 24-artifact
denominator. This does not establish defense equivalence or a general safety
bound. It does provide measured evidence that, on this constrained exporter
task, mandatory review did not add observed output correctness beyond prompted
voluntary review.

For contract-consistent guidance, required-review runs used 11.7 more observed
credits on average across five complete paired cost observations. Conflicting
guidance produced variable differences (mean -15.2 over six pairs); a lower
mean in that setting is not an isolated causal efficiency claim.
The full data retain the readiness failure, all exposure records and the
separate closure-versus-output distinction.

The next preregistered development question in ADVERSARIAL-CONTRIBUTOR.md
expands the adversary from message-only guidance to ordinary task contribution.
It is a new threat intervention, not a substitution for unsuccessful attacks
or a pooled stronger-looking result.

That extension is now complete: four development executions and a separate
24-execution replication. The corrected reviewer role can formally review
without authoring authority. Twelve adversarial executions generated thirteen
measured unsafe candidate snapshots; all were superseded, and no audited
publication revision disclosed synthetic fields. All 24 final outputs passed.
Both voluntary and required review did this, so no mandatory-review advantage
is asserted. The complete data retain that null comparison.

### Recorded operational failure and confirmation

The last replicated execution failed during worker readiness before any agent
activation. Four sessions connected; the reviewer session did not signal readiness
within the configured startup timeout. Cleanup and failed run-end evidence are
retained, with no final output audit and no observed credit report. The original
cause of the missing readiness signal is unknown; it is not labeled an agent
quality failure or a zero-cost success.

All 24 registered outcomes remain in the main denominator, including this failure.
Costs are reported only for observed executions, with explicit cost-observation
counts and missing paired contrasts. One fresh, separately named readiness
confirmation uses the same configuration without replacing the failed original.
This confirmation tests recoverability; it is not a selected successful primary
repetition or evidence of a repaired model-service root cause.

Use all observed outcomes, including null results and costs.
Do not pool development runs, earlier rule bundles or deterministic fixtures
into the new comparison.
