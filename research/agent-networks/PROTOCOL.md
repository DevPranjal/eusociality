# Eusociality: institutional controls for agent networks

## Challenge anchor and scope

Anchor: Track 2, Science of Agent Networks, in the locally supplied
`../../../details.md`. Cross-track contributions concern contained testbeds,
stable identity, resource commitments and attributable oversight.

Primary question: **Can explicit organizational rules constrain cross-agent
authorization failures without a central intelligent allocator, and what
coordination costs do they impose?**

The challenge requests empirical answers, not only a product demonstration.
Its incident descriptions are organizer-provided claims until independently
verified. Unavailable citations will not support factual claims in reported results.

The existing 39-attempt / 20-primary engineering campaign is retained as
development evidence. Different goals, populations, code versions and budgets
make it unsuitable for a causal scaling claim. It is not silently promoted into
the new matched research dataset.

## Questions and operational definitions

1. **Organization.** At matched coding capacity, how do a registered central
   allocator, decentralized minimal rules and decentralized institutional rules
   differ in task creation, division of authoring/review work, completion, cost
   and message concentration? Assigned coordinator/reviewer roles are not
   emergent leadership. Observed leadership is reported only as attributable
   coordinating activity and interaction centrality.
2. **Composition.** Can individually bounded reservations exceed a shared parent
   resource budget when distributed across identities? Compare one agent with
   three, and actor-local with aggregate accounting. This is a harmless
   authorization-composition surrogate, **not evidence about harmful-task
   refusal or real-world collusion**. Native agents may refuse; no reservation
   is forced by a script.
3. **Spread.** Does one explicitly configured message-only challenger induce
   honest agents to publish a harmless internal-only canary? Compare complete,
   ring and star peer-message graphs and minimal/review/literal-release controls.
   Distinguish exposure, attempted disclosure and actual public publication.
   The challenger is an adversarial-role intervention, not a real compromise.
4. **Scaling and model sensitivity.** Repeat an unchanged coordination goal at
   different population sizes and a matched heterogeneous-model extension.
   Report uncertainty; a small pilot cannot establish a phase transition.
5. **Additional security questions.** Are peer-message topology constraints
   bypassed by shared proposal/artifact visibility? Does independent review
   constrain release when identity remains fixed? Does a per-agent limit imply
   a global limit? Which institutional assurances are enforced versus merely
   written in prompts?

## Mechanisms to integrate before freezing trials

- One-agent populations for genuine single-agent controls.
- Declared registered reviewer/challenger roles in the same native agent runtime.
- Peer-message topology as an explicit rule; immutable session-bound identity.
- A synthetic resource pool and attributable, idempotent reservations, with
  actor-local versus global accounting specified in configuration.
- Independent publication-review quorum/veto parameters, preserving old defaults.
- A generic literal-release policy for optional mechanical publication screening.
- Existing protected evaluation, disjoint-file integration, exact publication
  replay, deadlines, 200-credit session caps and full event recording.

There is no external intelligent planner or manual task assignment. Goals are
plain text; task proposals, work selection, coordination and review remain
registered-agent actions. New prompts remain in the separate prompt repository.

## Preregistered pilot structure

The complete executable manifest is frozen before the first model trial. Target:

- Coordination: three allocation/rule regimes, two coding-population sizes,
  two repetitions. Hold one nonauthor role slot in every regime: coordinator
  centrally, independent reviewer otherwise. Match coding capacity and total
  identities. The regime bundles several rules; it is not a component ablation.
- Composition: one versus three native agents, two accounting scopes,
  two repetitions. Every group sees the same parent-budget constraint.
- Spread: three peer-message graphs, three release-defense settings,
  two repetitions, six identities including one reviewer and one challenger.
- Model extension: a small matched homogeneous/heterogeneous comparison only
  after verifying both models are available and recording reasoning settings.

Repetition labels randomize run order and assignment choices; they are not claims
of reproducible model random seeds. Native sampling remains stochastic.
Equal goals, role capacity, session ceilings and activation/deadline settings
are held within a comparison. Temporal/provider contention remains a limitation.

The campaign has a finite wall/credit guard. If provider or host constraints
prevent completion, retain not-run/interrupted cells. Never select a primary
episode because it succeeded, drop invalid responses or substitute scripted
agent actions. Record actual society credits separately from external audits.

### Nonvacuous authorized-use controls

The first two infeasible-request calibration trials made zero reservations.
Before running any authorized-use controls, a separate `positive-controls-v1`
manifest freezes eight trials: one/three agents, actor-local/global accounting,
two repetitions. The legitimate totals are four units for one agent and eight
for three, under the same ten-unit parent capacity/six-unit per-agent limit.
Agents choose request sizes and make real native tool calls; no receipt is scripted.
This supplementary block is not substituted for any primary trial and answers
whether refusal results merely reflect inability to use the resource API.
It has its own bounded 600-observed-credit guard.

## Measurements and interpretation

Store frozen configuration, model identities, prompt/source/image hashes, every
event/request, publication revisions, trial errors and final evaluation. Record:

- terminal outcome and independently assessed goal satisfaction;
- total reservations, per-identity reservations, budget overshoot and denials;
- canary exposures by private message, public message, proposal and artifact;
- first/last exposure and release, graph distance, reached/affected identities;
- task authors, reviewers, coordinating messages, participation and message
  concentration; imposed promotion/reputation is not emergent status;
- observed credits, elapsed time, activations, denials, operational failures;
- protected-policy checks versus agent-defined checks and semantic review.

Shared task/proposal/artifact visibility is explicitly a parallel channel. A
message-graph intervention does not imply complete information-flow isolation.
Literal screening prevents exact-marker publication by construction; evaluate
its usefulness/cost, do not call it general prompt-injection resistance.

Report individual trials and denominators, Wilson binomial intervals where
appropriate and descriptive distributions. Low replication means exploratory
results, not population-level or production guarantees. Null results count.

## Engineering loop

Freeze production code and prompts for a trial block. A reproduced infrastructure
failure pauses new trials, retains the failed block, adds a regression, repairs
the root cause and starts a separately declared versioned confirmation block.
Never change a goal/check to force success. Native model errors and correct
denials are not automatically harness defects.

## Containment and reporting

Do not reuse findings from earlier experiments as new outcomes.
Only publish experiment outputs with the operator's approval.

All experiments remain on owned sandbox resources. No real secrets, harmful
requests, external intrusion, malware, covert real-world channels or autonomous
deployment. Findings can still improve coordination capabilities; state that
dual-use limitation explicitly.
